# Data and full-market research

TradeMaster provides two complementary Parquet-and-DuckDB data pipelines tailored to different units of work:

- **Point-in-time queries and data snapshots (`DataPortal`).** Designed for targeted dataset reads and backtest preparation, `DataPortal` tracks catalog coverage at the `(instrument, session)` key level and fetches missing slices on demand.
- **Resumable full-universe acquisition (`FullAResearchPlanner`).** Designed for multi-year, market-wide A-share studies, the bulk planner schedules deterministic provider requests into a content-addressed manifest and records the exact outcome of every task—including verified empty responses—so interrupted downloads resume cleanly without re-querying completed partitions.

## From a request to a point-in-time table

On the canonical portal path, a `DatasetRequest` specifies the target dataset, instrument universe, projected fields, and date range. Calling `ensure(request)` checks DuckDB coverage and populates missing partitions when a live provider is configured, after which `query(request, as_of=...)` returns an Arrow table filtered strictly by that `as_of` visibility cutoff. To freeze inputs for reproducible simulation or factor materialization, `snapshot(SnapshotRequest(...))` binds the normalized requests and content-addressed Parquet digests into an immutable **data snapshot** manifest that `load_snapshot(snapshot_id)` can reopen offline. Throughout this pipeline, availability policies explicitly separate three timestamps that often diverge in financial data: the fiscal period end of a statement, the wall-clock time a file was downloaded, and the first timestamp at which a strategy could legitimately observe the record. ## From a download plan to an evaluation

Full-market factor research preserves an unbroken cryptographic chain from raw Tushare Pro requests to published quantile diagnostics. Planning freezes the target A-share universe, trading calendar, and endpoint tasks under a SHA-256 plan digest (`DownloadPlanManifest`), and each completed task records the digest of its immutable Parquet output. Downstream panel manifests bind those raw task artifacts to dense `(instrument, session)` panels, point-in-time financial statement joins, and forward-return labels, while evaluation manifests bind the panel and factor artifacts to exact evaluation parameters—allowing any reported IC or quantile spread to be traced back to the exact provider responses that produced it.
