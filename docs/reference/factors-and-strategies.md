# Factors, signals and strategies

TradeMaster separates alpha research, portfolio construction, and trade execution into three distinct layers:

- **Factors** measure a point-in-time characteristic for an instrument at an observation timestamp—such as lookback price momentum or trailing return on equity.
- **Signals and strategies** map cross-sectional or time-series factor scores onto desired portfolio weights or share counts stamped with causal decision and earliest-execution times.
- **Execution engines** enforce venue lot rules, price limits, cash reserves, and T+1 settlement to determine realized fills (see the [daily snapshot API](snapshot-backtest.md) and [event runner](execution.md)).

Isolating ranking and allocation logic in Python while delegating market microstructure to Rust ensures that modifying a stock-selection rule never alters venue validation, and changing exchange constraints never leaks into factor code. In [contracts.py](../../python/trademaster/contracts.py), `Factor.compute(FactorContext)` emits typed Arrow factor tables, and `SignalGenerator.generate(SignalContext)` consumes those scores alongside the earliest permitted execution timestamp; event-driven callers may also implement `EventStrategy.on_bar(StrategyView) -> list[OrderIntent]`, whereas close-time portfolio strategies return target weights from a `DecisionDay` via the [snapshot callback](snapshot-backtest.md). ## Calculate and save a factor

`FactorExecutor` evaluates a factor definition over an Arrow input table within a `FactorContext` that binds the `as_of` visibility cutoff and input **data snapshot**. Around raw execution, `FactorManager` persists each run as a content-addressed materialization recording the versioned `FactorDefinition`, input table digests, universe/date scope, and upstream parent materializations—allowing downstream strategies and evaluators to reuse verified Parquet outputs directly while ensuring that any change in code, parameters, or upstream data produces a distinct materialization ID. [Factor guide](../factor-management.md) · [Contribution rules](../../python/trademaster/factors/AGENTS.md)

| Implementation | Interfaces and architectural role |
|---|---|
| [factors package](../../python/trademaster/factors/__init__.py) | `FactorRegistry` resolves versioned definitions, `FactorExecutor` validates outputs against `factor_output_schema()`, and core classes implement momentum, value, close-level, and composite factors. |
| [management.py](../../python/trademaster/factors/management.py) | `FactorDefinition` binds identity, parameters, and upstream dependencies; `ManagedFactorRegistry` validates registrations and topologically sorts parent factors in DAG order. |
| [storage.py](../../python/trademaster/factors/storage.py) | `FactorManager` materializes and verifies persisted factor tables, `FactorArtifact` pairs Arrow/Parquet values with a `FactorMaterialization` manifest, and `FactorCatalog` indexes artifacts by scope and lineage. |
| [builtin.py](../../python/trademaster/factors/builtin.py) | `builtin_managed_factor_registry()` assembles the standard executable factor catalog shared by CLI commands and first-party strategies. |
| [cross_section.py](../../python/trademaster/factors/cross_section.py) | `CrossSectionTransformSpec` and `CrossSectionCompositeFactor` govern per-timestamp cross-sectional grouping (such as industry neutralization), winsorization/clipping, standardization, directional signs, weights, and missing-value handling. |
| [fundamental.py](../../python/trademaster/factors/fundamental.py) | `fundamental_factor_suite()` registers managed value, quality, growth, and balance-sheet factors along with their multi-factor composite. |
| [evaluation.py](../../python/trademaster/factors/evaluation.py) | `FactorEvaluator` joins a verified materialization against causal forward-return labels to compute IC, rank IC, quantile returns, and signal turnover, while `FactorEvaluationStore` persists the diagnostics. |
| [public_library.py](../../python/trademaster/factors/public_library.py) | Source, candidate, and collection records track licensing restrictions, provenance, dependencies, and review status; `PublicFactorStore` persists and validates the catalog. |
| [public_cn.py](../../python/trademaster/factors/public_cn.py) | `builtin_public_factor_library()` compiles the surveyed A-share public factor catalog, distinguishing documented formulas that lack an executable binding from compute-ready definitions. |
| [public_factors.py](../../python/trademaster/factors/public_factors.py) | `public_executable_factor_suite()` binds reviewed Huatai and Guotai Junan factor implementations to managed definitions so only audited candidates can emit values. [Public library guide](../public-factor-library.md) |
| [Command dispatcher](../../python/trademaster/factors/__main__.py) | Implements the `tm-factor` CLI for definition inspection, dependency-graph rendering, materialization, integrity verification, factor evaluation, and public-library queries. |

## Turn observations into targets

Signal generators and strategy packages bridge verified factor scores or price series to causal execution inputs without embedding exchange accounting rules:

| Module or package | Provided interfaces and ownership |
|---|---|
| [Signal generators](../../python/trademaster/signals/__init__.py) | `TopNTargetWeightGenerator` ranks an eligible cross-section into equal or weighted portfolio targets, while `ThresholdQuantitySignalGenerator` emits discrete share targets on threshold crossings; both consume `SignalContext` and output typed Arrow signal tables stamped with decision and earliest-execution times. [Signal contribution rules](../../python/trademaster/signals/AGENTS.md) |
| [Strategy namespace](../../python/trademaster/strategies/__init__.py) and [strategy guide for contributors](../../python/trademaster/strategies/AGENTS.md) | Houses first-party strategy implementations under strict separation between data loading, factor scoring, portfolio construction, and Rust order execution. |
| [demo.py](../../python/trademaster/strategies/demo.py) | Implements `cross_sectional_momentum`, `moving_average_cross`, and `macd_cross` over historical closes, alongside `MacdTiming.on_close` (which uses incremental `MacdSpread` state to update 12/26/9 EMAs in O(1) per close). Consult the [strategy example](../examples/tushare-strategies.md) for indicator warm-up windows, parameters, and the distinction between holding active targets (`None`) versus exiting to cash (`{}`). |
| [Industry public API](../../python/trademaster/strategies/industry_fundamental/__init__.py) and [module entry point](../../python/trademaster/strategies/industry_fundamental/__main__.py) | Provides stable Python exports and the CLI entry point for the managed-factor industry-rotation strategy; see the [usage guide](../../python/trademaster/strategies/industry_fundamental/README.md) for portfolio selection options. [Package rules](../../python/trademaster/strategies/industry_fundamental/AGENTS.md) |
| [Compatibility exports](../../python/trademaster/strategies/industry_fundamental_top5/__init__.py) and [argument parser](../../python/trademaster/strategies/industry_fundamental_top5/__main__.py) | Preserves the legacy module path and ten-year historical CLI flags. [Reproduction notes](../../python/trademaster/strategies/industry_fundamental_top5/README.md) · [Package rules](../../python/trademaster/strategies/industry_fundamental_top5/AGENTS.md) |
| [selection.py](../../python/trademaster/strategies/industry_fundamental_top5/selection.py) | `IndustryFundamentalStrategy` and `IndustryFundamentalConfig` enforce top-industry and per-industry constituent caps over scored candidates to emit exact target weights. |
| [data.py](../../python/trademaster/strategies/industry_fundamental_top5/data.py) | `StrategyDataCache` binds provider request parameters to hash-verified raw and derived Parquet tables, sharing cached objects with full-market research workflows. |
| [real.py](../../python/trademaster/strategies/industry_fundamental_top5/real.py) | `run_real_strategy(config=..., data_root=..., output_root=...)` orchestrates point-in-time universe membership, financial statement joins, factor scoring, target generation, event-runner execution, and report rendering across both historical-interval and static-membership configurations. |

When modifying signal or strategy logic, run the [momentum and signal tests](../../tests/test_momentum_and_signals.py), [value/composite and threshold tests](../../tests/test_value_composite_threshold.py), [point-in-time regression cases](../../tests/test_m2_review_regressions.py), and [data-to-signal integration](../../tests/test_factor_signal_data_integration.py), alongside strategy-specific suites for [demo crossovers](../../tests/test_demo_strategies.py), [industry ranking and allocation](../../tests/test_industry_fundamental_top5.py), and [the industry data cache](../../tests/test_fundamental_strategy_data_cache.py).
