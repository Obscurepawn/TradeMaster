# M6: End-to-End Backtest Bundles and Deterministic Replay

**Status:** Completed | **Date:** 2026-08-11 | **Scope:** Content-addressed run bundles, Rust runner orchestration, and cache-first Tushare Pro verification (`trademaster.e2e`, `tm-runner`) | **Updated-by:** [Python and Rust Native Backtest Interface](20261105-python-rust-backtest-interface.md)

## Motivation and Scope

Milestone M6 connects M1 **data snapshots**, M2 factors and signals, the M3–M4 Rust execution runtime, and M5 standalone reports into content-addressed end-to-end run bundles (`trademaster.e2e`). Both cross-sectional A-share portfolio rebalancing and single-instrument stock/ETF strategies execute through the same Rust event loop and produce portable bundles that a fresh process can verify offline byte for byte.

*(Note: In M6, Python invoked `tm-runner` over canonical JSON; [Python and Rust Native Backtest Interface](20261105-python-rust-backtest-interface.md) subsequently moved event execution and `tm-replay` in process via `tm-python` while preserving byte-identical bundle replay.)*

## Bundle Contract and Causality Rules

- **`RunnerRequest` and `tm-runner`:** `RunnerRequest` binds the `run_id`, `strategy_id`, signal `snapshot_id`, execution market `snapshot_id`, initial cash, checked `InstrumentSpec` definitions, UTC session bars, and scheduled signals (using 8-decimal scaled integers for money/prices and exact integers for share quantities). `tm-runner` rejects unknown JSON fields, non-canonical scaled integers, and unregistered instruments, executes the M4 `EventLoop`, and emits the full canonical audit trace (signals, order intents, acceptances, rejections, fills/expiries, ledger effects, and account snapshots).
- **Dual snapshot provenance:** A signal computed after session `T` close observes a data snapshot with `as_of` at `T` close, whereas next-open execution on `T+1` requires market bars spanning `T+1`. Each signal retains its originating signal `snapshot_id` alongside the run's execution market `snapshot_id`.
- **Ledger-derived exposures and bundle verification:** Portfolio exposures are computed directly from Rust account snapshots and actual marked holdings rather than target weights. `verify_e2e_bundle()` rehashes every referenced snapshot manifest and Parquet file, replays the Rust execution trace, recomputes exposures, and verifies that the regenerated HTML report matches the saved report SHA-256 without leaking credentials or host-specific absolute paths.

## End-to-End Verification Scenarios

1. **Synthetic cross-sectional rebalance:** Rebalanced three A-share instruments across multiple sessions with close-to-next-open (`T+1`) execution, 100-share board lots, T+1 lot unlocking, fee schedules, industry/size exposures, benchmark alignment, and complete portfolio liquidation.
2. **Synthetic single-instrument timing:** Exercised buy and sell threshold crossings, fills, idle non-signal sessions, final holdings, and exact NAV conservation.
3. **Live Tushare Pro cache-first runs (`artifacts/e2e-real/`):**

## Comprehensive Review and Final Checks

Following initial end-to-end completion, a single cross-system audit identified 1 Critical, 4 High, and 2 Medium issues: unverified links between bundle inputs and outputs, stock stamp-duty/transfer fees applied to ETFs, missing multi-rebalance exit test coverage, hard-coded exposure placeholders, omitted Rust audit traces in bundle outputs, and incomplete price-adjustment metadata in report charts. All seven findings were resolved and covered by `verify_e2e_bundle()` regressions:

- **Python checks:** 132 passed, 0 skipped (with live Tushare credentials read from an external `0600` file; 0 credential matches across code, data, and artifacts), Ruff, strict `mypy` (34 source files), and wheel/sdist builds.
- **Rust & packaging checks:** 41 workspace tests and doc-tests, `cargo fmt --check`, `cargo clippy -D warnings`, `git diff --check`, and isolated tarball verification across `tm-core`, `tm-engine`, and `tm-runner` (patching unpublished workspace dependencies to local paths so Cargo did not resolve an unrelated crates.io package named `tm-core`).
